# 台阶 · 不给你答案的编程陪练

> 卡住的时候，AI 应该像学长一样先问你一句「你觉得问题出在哪」，而不是直接把答案贴给你。

「台阶」是一个面向编程初学者的**分级提示**陪练。你把出错的代码和报错贴进去，它不会一次给全答案，而是让你自己一阶一阶往上走：

```
L1 方向提示  → 只谈现象和方向，不给代码
L2 伪代码    → 讲清关键步骤和该用的概念，仍不给成品
L3 最小修复  → 指出改动的那一处，给出关键片段
变式题       → 换一个场景考同一知识点，答完由它批改
```

## 它解决了什么

现在大多数「AI 编程助手」面对初学者时反而有害：直接给完整代码，学生复制粘贴就跑通了，但什么都没学会。真正的问题不是「拿到能跑的代码」，而是**建立自己定位错误的能力**。

「台阶」把这件事拆成可度量的过程：

- **强制逐级**：三级提示由你点按钮显式索取，AI 不替你做决定；
- **防漏答案**：L1/L2 回复里如果混进了成品代码，前端会自动把它盖住（`looksLikeLeak`）；
- **留痕**：每次求助的错误类型、用到第几级、平均深度都记在本地，越用越能看出「我在哪类问题上最依赖被扶」。

## 快速开始

```bash
pnpm install
pnpm dev        # http://localhost:5173
pnpm build      # 类型检查 + 产出 dist/
pnpm preview    # 预览构建结果
```

打开页面后填三项：

| 项 | 说明 |
|---|---|
| 网关地址 | 默认 `https://di.whu.edu.cn/api/v3`（武汉大学 DSH 活动网关） |
| API Key | 你自己的 Key，**只存本地 localStorage** |
| 模型 | 默认 `deepseek-v4-flash`；拉到模型列表时可下拉选 |

点「测试连接」会发一条最短请求验证 Key / 地址 / 模型名，通过了再「开始使用」。

## 架构

纯前端，零后端，浏览器直接连网关（OpenAI 兼容协议）。

```
src/
  types.ts        领域模型（Level / Phase / ChatMessage / ErrorStat / ApiConfig）
  api.ts          SSE 流式调用 + 模型列表；带 AbortSignal 与错误详情
  prompts.ts      三级提示词、变式题、批改、分类提取、泄漏检测
  storage.ts      localStorage：配置 / 统计 / 历史（均带 try-catch 容错）
  App.tsx         状态编排：阶段机、看门狗、统计口径
  components/     SetupCard / InputPanel / ChatPanel / StatsPanel
```

几个关键设计：

- **统计口径**：一次求助按「用到的最深级别」记一次，L2 之后又要 L3 不会被算成两次求助（`record` + `bump`）。
- **精确均值**：累计 `levelSum` 再算平均，不做逐次取整，避免长期偏差。
- **看门狗**：35 秒没收到新字符就自动中止并给出可读提示，同时提供「停止」按钮，演示时不会永久卡在「正在想…」。
- **未归类兜底**：模型偶尔漏写 `【类型：xx】`，这类求助会落进「未归类」，不静默丢失。

## 关于 API Key

Key 只存在**你自己浏览器**的 localStorage（键名 `taijie.config.v1`），不经过任何服务器——因为本项目没有服务器。

因此：

- 公开部署（GitHub Pages / Netlify）时，**不要把 Key 写进代码或提交到仓库**；评委打开链接后自己填即可；
- 换电脑、清浏览器数据后需要重新填；
- 点「改设置」可以只换 Key，当前对话和统计保留。

## 部署

`vite.config.ts` 里 `base: './'` 用相对路径，所以以下都能直接用：

- **Netlify**：构建命令 `pnpm build`，发布目录 `dist`
- **GitHub Pages**：`pnpm build` 后把 `dist` 推到 `gh-pages` 分支
- 本地直开：`pnpm preview`

## 已知取舍

- 单用户、单会话：不做账号系统，刷新后对话不保留（统计会保留）。
- 变式题批改只判思路对错，不给完整重写答案——与 L1/L2 的克制一致。
- 不做代码执行：本工具的目标是「看懂自己的错」，不是在线跑代码。
